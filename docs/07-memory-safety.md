# 07 · 内存安全

**这篇讲什么**：为什么会 wedge、哨兵怎么判、KV 为什么看起来「越跑越紧」。

---

## 1. wedge 长什么样

| 项 | 状态 |
|---|---|
| ping | 通 |
| TCP :22 | 接受 |
| SSH banner | **超时** |
| OOM killer | 常常**没有** |
| 恢复 | 25–40 分钟自愈，或断电 |

GB10 统一内存：host 与 GPU 同一块约 128 GB。回收来不及 ≠ 「再少用一点就安全」。要靠 **min_free 余量 + 外部哨兵**。

**禁止**对已 wedge 的节点轮询 SSH（堆会话拖慢恢复）。

## 2. 哨兵判据（现役）

- 绝对下限 `MemAvailable` **1024 MB**，不得改成 8192「更宽松」——8192 在本配置会秒杀。
- PSI 只与 `avail<16384` **合取** 且 `psi>50`。
- 相位控制器：`v41-mg-phase.sh start`，终态留 **load**。
- 脚本在 [`scripts/memguard/`](../scripts/memguard/)。

## 3. KV 用过不还（A，2026-09-28）

池按**写入**逐页占宿主内存，`/flush_cache` 后空闲仍大约少掉「写过的那些页」。刚起服的空闲读数最多虚高**一整个池**。判余量看运行一段时间后的连续最低值，不要看 boot 后第一分钟。

## 4. 读放大会假装泄漏

在含 2 TB 权重的目录上 `grep -r` 会以数百 MB/s 灌页缓存，`MemAvailable` 锯齿、`anon` 却是平的。先排除读放大再谈泄漏。

## 5. 09-14 vLLM 未打 Engram 补丁

历史：不把 Engram 放到盘上，每 rank 装不下 → wedge。现役 knapcio 路径是 **Engram on NVMe**，机制不同，但结论一样：**算出装不下就不要起四台**。
